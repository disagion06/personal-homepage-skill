# Demo 产出说明

这份 `index.html` 是上面的 brief 走完 SKILL.md 全部九个阶段的结果。
看它是为了知道**每一阶段的产出应该长什么样**，而不是直接抄。

---

## 阶段 4 · 设计评审的六维打分

| 维度 | 分 | 判断依据 |
| --- | --- | --- |
| 概念 | 7.5 | "工程师的规格书"这个母题基本成立：编号、分栏、等宽数字、无装饰。但换成一个设计师也能用，所以没到 8.5 |
| 哲学一致性 | 8 | 全篇只有一种语言：黑 + 白 + 单一红、左对齐、细线分隔、无圆角、无阴影。没有外来元素 |
| 视觉层级 | 8 | 姓名 72px / 正文 16px ≈ 4.5 倍，区块标题 13px 大写字母间距拉开，层级清晰 |
| 细节执行 | 7.5 | 所有间距是 8 的倍数；`font-variant-numeric: tabular-nums` 让编号和数字对齐；扣分项是手机端编号列宽偏窄 |
| 功能性 | 8 | 首屏只有一个动作（看经历）；项目只留 4 个；技术栈分 4 组而不是堆一长串 |
| 创新性 | 7 | 没有菱形/印章/渐变光晕这些 AI 惯性装饰。但"瑞士国际主义"本身是成熟套路，所以不给高分 |

**总分不高的部分是诚实的。** 一个干净的工程师主页本来就该是 7 分档，
硬要打到 9 分反而会出现无意义的装饰。

## 按评审做出的改动

第一版写完后改了三处：

1. **首屏原本有一个"查看项目"按钮** → 删掉。区块就在下面，按钮是多余入口（功能性）
2. **技术栈原本是一段逗号分隔的长文本** → 改成 4 组带细线的列表。可扫读性完全不同（视觉层级）
3. **项目卡片原本只有标题和描述** → 加了"角色"和"技术栈"两行，构成 名称/角色/描述/技术栈 的四层层级（细节执行）

## 动效说明（阶段 5）

只用了一项：**stagger 进场**（`.reveal` → `.in`）。

- 包在 `@media (prefers-reduced-motion: no-preference)` 里，用户要求减少动效时整段不生效
- 初始隐藏是**由 JS 添加 `.js` class 之后**才成立的，所以 JS 失败或禁用 JS 时内容默认可见
- 没有选 letter-spacing 收束、odometer、3D 装饰 —— 与"别太花"的要求冲突

## 脱敏说明（阶段 7）

这个 demo 里的 `demo@example.com` 和 `github.com/example` 都是**假值**，
所以扫描不会报警。真实场景里：

```bash
node scripts/redact.cjs scan "demos/minimal-portfolio"
node scripts/redact.cjs build "demos/minimal-portfolio" --policy mask-high
```

用 `mask-high` 而不是默认的 `mask-all`，因为**求职页面的联系方式是故意公开的**
（见 `references/05-隐私脱敏规则.md` 里「必须让用户决定的三种情况」第 1 条）。

## 你可以从这个 demo 学到什么

- 没有图片也能做出不单薄的页面（靠排版和层级，不靠图）
- 「不选什么 + 为什么」要写进记录里
- 评审分数打得诚实比打得高有用
- 动效的降级路径要在写的时候就设计好，不能事后补
