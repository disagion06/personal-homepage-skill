# 07 · 常见问题

---

## Q：用户说"我没有设计稿，你随便发挥"

不要直接开写。至少确认两件事：**给谁看**（决定信息优先级）和**有什么素材**（决定能不能放图）。

然后就按 SKILL.md 的六条风格参考里挑一个，**说明理由**再动手。
"随便发挥"通常意味着"你替我决定，但要说清楚为什么"。

---

## Q：用户只有一个简历 docx，没有图片

完全可以做。纯文字版式（报纸排版、极简衬线、大字排版）反而更容易出彩。
不要因为没有图片就去找图库 —— **引入外部图片会违反 R2**。

可以在首屏用 CSS 几何形状代替人像，或者干脆不放。

---

## Q：用户要 React / Vue / Tailwind

先解释代价：一旦引入框架，就做不到"双击打开的单文件"，必须有构建步骤，
发布也变复杂。如果用户坚持，那就不适用这个 skill 的 R1，
但仍然需要 `check-page.cjs` 的其它检查（alt、ASCII 文件名、脱敏）。

**多数情况下用户说"用 React"其实只是想要"现代一点"**，说服他看两个方向的截图就行。

---

## Q：页面在本地能看，发布后图片全裂

按顺序排查：

1. 图片 `src` 是**静态写死**的吗？（R3）
2. `assets/` 目录**一起推上去了**吗？
3. 文件名有**中文/空格**吗？（R4）
4. 路径大小写对得上吗？（Linux 服务器大小写敏感）
5. 用了根路径 `/assets/a.jpg` 吗？项目站点在子路径下，要用相对路径
6. 目录是 `_` 开头但没放 `.nojekyll` 吗？

```bash
node scripts/check-page.cjs "<目录>"    # 这个会把缺失的图片一次列出来
```

## Q：视频点开是黑屏

九成是 **HEVC 编码**。检测：

```bash
node scripts/preflight.cjs "<素材目录>"
```

看到 `hvc1` / `hev1` 就必须转 H.264：

```bash
ffmpeg -i "原片.mp4" -c:v libx264 -crf 23 -c:a aac -movflags +faststart "assets/video-01.mp4"
```

另一个可能：没抽首帧封面，未播放时是黑框（不是黑屏但看起来像）。
`-ss 1` 而不是 `-ss 0`，首帧常是纯黑。

## Q：PSD 能不能直接放到网页上

不能。`<img src="x.psd">` 什么都不会显示。

导出预览图（PNG/JPG），在图注里注明源工程信息，例如
「源工程 Photoshop (13111×720)」。这样既展示作品，又体现专业度。

`.aep` / `.ai` 更没法展示 —— **不要放进 assets**，只在技能标签里写"After Effects"。

## Q：手机上能左右拖动，右边有空白

某个元素比视口宽。控制台跑：

```js
[...document.querySelectorAll('body *')]
  .filter(el => el.getBoundingClientRect().right > document.documentElement.clientWidth + 2)
  .map(el => el.tagName + '.' + el.className)
```

常见元凶：长英文串没断行（加 `overflow-wrap: break-word`）、
固定 `width: 1200px`（改 `max-width`）、`100vw`（改成 `100%`，`100vw` 含滚动条宽度）、
负 margin 的装饰元素。

---

## Q：自检报"文字重叠"，但看截图明明没重叠

**这是已知误报。** 检测器把同一行相邻的加粗片段或数字片段判成了重叠。

处理：看截图确认，确认无误就忽略。
**不要为了消警告去改好端端的排版** —— 那会让本来正常的版式变糟。

---

## Q：截图里作品卡区域是空白的

动效元素初始 `opacity: 0`，截图时还没显形（stagger 的截图盲区）。

处理：复制一份站点，把 `opacity` 强制成 1，在副本上截图验证布局。
**不要改产品文件。**

---

## Q：用户说"帮我发布"，但他没说仓库名

别自己起一个含糊的名字。给他三个建议挑：

- 求职用：`resume` / `portfolio`
- 个人站：`<名字拼音>.github.io`（这是个用户站点，链接更短更正式）
- 项目站：`my-portfolio`

同时提醒：**免费账号的 Pages 要求仓库公开**，公开意味着所有人能看。

---

## Q：脱敏把联系方式全删了，用户不满意

说明你没有按第 7 阶段的「必须让用户决定的三种情况」走。

求职简历里联系方式**本来就该公开**。正确做法是先问：

> "手机号和邮箱是打算公开给招聘方的吗？如果是，我保留；如果不是，我打码。"

用 `--interactive` 或者 `--policy mask-high`（只打高危，邮箱等中危保留）。

---

## Q：用户想改版，但上下文全丢了

这正是 `rule.md` + `log.md` 的用处。让用户把这两个文件找出来，
里面应该有风格、色板、硬约束、每个阶段做了什么。

没有的话，让他把现有 `index.html` 给你，你读一遍反推出规则，**顺便补写这两个文件**。

---

## Q：能不能加访问统计 / 评论 / 联系表单

GitHub Pages 是**纯静态**，没有后端。

| 需求 | 可行方案 |
| --- | --- |
| 访问统计 | 第三方脚本（违反 R2，需用户明确同意）；或干脆不加 |
| 评论 | 同上（giscus 之类需要 JS 外链） |
| 联系表单 | 做不到。用 `mailto:` 链接代替 |
| 博客 | 可以做，但每个页面都要有静态 HTML，且导航要手写 |

**如实告诉用户限制**，不要拼凑一个半残的方案。

---

## Q：能不能不上 GitHub，用 Vercel / Netlify

能，但那是另一条路。这个 skill 的 `deploy.cjs` 只做 GitHub Pages。

如果用户明确要 Vercel/Netlify，告诉他：那两个支持拖拽上传或 CLI 部署，
`npx vercel` / `npx netlify deploy` 即可，但它需要额外注册账号。
**GitHub Pages 的优势是零额外账号、和代码同源、免费。**
