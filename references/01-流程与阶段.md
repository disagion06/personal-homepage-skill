# 01 · 真实手工实操全记录

这是一次真实做个人主页时，人和 AI 一步步走下来的完整过程。看它是为了知道**每个阶段实际会发生什么**，
而不是只记住一个理想化的流程图。

---

## 起点：用户的原话

> 「我需要建立一个个人作品展示网站，整个过程我需要和 obsidian 同步，
> 先建立一个 rule.md 的文档，记录我在建站过程中的规则，同时建立一个 log.md 的文件，
> 以便我每个阶段记录开发进度，建立好文件后，等我下一步指令」

**第一件事不是写代码，是建两个文档。** 这个习惯很值得抄：后面每次改版都能快速恢复上下文。

## 阶段 1 · 取材

> 「我把个人简历信息都放进工作区了，帮我做一个个人简历单页 index.html；
> 信息从个人简历抽，图片文件下的 png 图片，工作照当人像，单文件 HTML，
> 内嵌所有 CSS+JS，不要 npm 不要 React，纯静态前端，双击能在浏览器打开」

AI 做的事，按顺序：

1. 先在工作区里**找**简历文档（`*.docx`）和图片目录 —— 找不到就继续搜常见位置，不要瞎猜路径
2. 提取简历文本
3. **逐张看图片**，判断哪张是人像、哪张是作品图、每张对应什么作品
4. 把图片复制进 `assets/`，**用拼音重命名**（原话：避免空格和特殊字符）

> 关键点：`工作照当人像` 这种指令，只有**真的看了图**才能落实。纯文件名启发式会认错。

## 阶段 2 · 生成骨架

- 先写页面结构与样式
- 再补交互脚本（作品渲染、筛选、灯箱、移动菜单、滚动动画）
- 然后跑自检、生成桌面与移动端截图
- 看截图 → 修问题

第一版自检报出来的问题（很典型，你也会遇到）：

| 问题 | 修法 |
| --- | --- |
| 作品图片路径靠 JS 注入 | 改成静态 `src`，写死在 HTML 里 |
| 时间轴圆点不显示 | 加 `display:block` |
| 信息卡挤成 4 列 | 改成 5 列布局 |
| 按钮触控区太小 | 提高触控尺寸与字号 |

> **「图片路径靠 JS 注入」是最高频的翻车点。** 本地预览正常，发布后全裂。

## 阶段 3 · 风格定向

用户给了一个风格库（6 部电影 + 各自色板），要求 AI **挑一部并说明理由**：

> 「我要维斯・安德森电影的视觉气质。从下面 6 部挑一部你认为最符合『我』气质的，作为色板和调色灵感源，
> 告诉我你挑了哪部」

AI 挑了《法兰西特派》，理由：它是关于"报社编辑部出版最后一期杂志"的电影，
报纸排版、章节叙事、油墨印刷美学，对应"新媒体运营 + 内容创作 + 严谨数据"的身份定位。

产出的色板：报纸奶油 `#F2EDE1` / 墨蓝 `#1F2A44` / 印刷红 `#C62828`。

> 关键点：**风格必须与内容身份绑定**。挑风格时说"这个好看"是废话，要说"为什么这个适合你"。

## 阶段 4 · 设计评审（最有价值的一步）

用一套 5 维度方法论审视，实际输出 6 项打分：

| 维度 | 分 | 失分原因 |
| --- | --- | --- |
| 概念 | 8.5 | 母题与身份强绑定，不可替换 |
| 哲学一致性 | 7.5 | **圆形人像是现代极简语言，韦斯·安德森是方形对称世界** |
| 视觉层级 | 7 | 作品卡内层级不足（类别 12px 与标题对比 <2.5 倍） |
| 细节执行 | 6.5 | 间距未走 8pt 网格、FIG 编号 10px 几不可见、装饰略散 |
| 功能性 | 7 | hero 元素层层叠、入口过多 |
| 创新性 | 8 | 菱形装饰、红章有轻微 AI 惯性 |

**然后按失分项直接重写**，不是写报告就完事：

1. 圆形头像 → **方形报纸肖像照**（墨线双框 + 斜体图注 `PORTRAIT`）
2. 报头 → **报纸栏题**：期号/版本/日期三栏 + 居中刊名 + 栏目表导航
3. 间距统一 **8pt 网格**
4. 作品卡加**报纸图注行**：斜体类别居左、`FIG.01-08` 编号居右
5. Hero **编排式加载动效**（报眉→刊名→肖像→导语→CTA 依次压印）
6. 编者按**首字下沉** + 页脚「Printed in Kunming」

## 阶段 5 · 动效

用户给了 10 项候选菜单，AI 选了 7 项，并**明确说明哪三项不选以及为什么**：

> 未选 ③ 双层 cursor（现代 UI 语言与报纸复古冲突）、① 静态 / ⑩ 朴素（与"加动效"矛盾）

「不选什么 + 为什么」和「选什么」一样重要。

## 阶段 6 · 素材扩容（PSD / AEP / 视频）

用户问：文件夹里那些 `psd`、`aep`、`mp4` 能不能也放进去？

处理方式（**这就是 C2/C3/C4 的来源**）：

| 素材 | 处理 |
| --- | --- |
| 3 个 MP4 | 两个原片是 **HEVC 编码，浏览器播不了** → 转 H.264（168MB→75MB）；各抽首帧做封面 |
| 179MB 的 PSD | 无法直接展示 → **导出预览图**作为平面设计作品入站，图注标注源工程尺寸 |
| 2 个 AEP | 工程文件无法网页展示 → **只在技能标签里佐证**，不放进 assets |

还有个细节：抽帧时发现 0.8s 处是**黑帧**，要换个时间点重抽。

## 阶段 7 · 自检

每次都跑截图自检，检查：JS 错误 / 资源错误 / 横向溢出 / 文字重叠。

**反复出现的情况**：文字重叠告警是**误报**——检测器把同一行相邻的加粗或数字片段判成了重叠。
处理方式：看截图确认，确认无误就忽略，不要为了消警告去改好端端的排版。

另一个坑：**stagger 动效的元素初始 `opacity:0`，截图工具截不到**，
要做一个"动效已完成"的临时副本来验证布局。

## 阶段 8 · 敏感信息检查 → 上线

AI 扫出手机号 3 处、QQ 邮箱 2 处，并解释了风险（邮箱前缀就是 QQ 号，可被反查/爬虫收集）。

然后生成发布计划：装 Git → 建公开仓库 → 加 `.gitignore` 排除 `_shots/` `_backup/` →
5 条 git 命令推上去 → Settings → Pages 选 main 分支 → 等 1 分钟拿链接。

---

## 从这个记录里能提炼出什么

1. **先建文档**（rule.md / log.md），成本极低，收益极高
2. **取材要真的看图**，不要靠文件名猜
3. **素材必须 ASCII 命名**，否则发布裂图
4. **风格要与身份绑定**，并说清理由
5. **评审要给分 + 给失分原因 + 立刻改**
6. **动效要说明不选什么**
7. **PSD/AEP/HEVC 各有各的处理方式**
8. **自检会误报，要看截图确认**
9. **发布前必须扫隐私**
