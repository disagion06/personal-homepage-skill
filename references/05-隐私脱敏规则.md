# 05 · 隐私脱敏规则

第 7 阶段用。核心判断标准只有一句：

> **这条信息被陌生人看到，会不会给用户带来实际伤害？**

会 → 处理。不会 → 可以保留（但要让用户决定，不是你决定）。

## 四种处理动作

| 动作 | 效果 | 什么时候用 |
| --- | --- | --- |
| `mask` 打码 | 按规则掩码：`138****8000`、`de***@example.com`、`张**` | 默认，保住结构又保住隐私 |
| `delete` 删除 | 把这处文本删掉 | 密钥、令牌这类不该有任何痕迹的 |
| `hideblock` 隐藏整块 | 删掉文本，**并把所在的整个条目/卡片隐藏** | 整条信息都该消失时（如整行联系方式） |
| `keep` 保留 | 原样公开 | 求职场景里故意公开的联系方式、学校、公司 |

`hideblock` 很关键：如果只删掉值，会留下"电话："这样的空标签，很难看。
隐藏整块会把这个条目一起收起。

---

## 策略预设

```bash
node scripts/redact.cjs build "<目录>" --policy mask-all      # 默认，最省事
node scripts/redact.cjs build "<目录>" --policy mask-high     # 只打码高危
node scripts/redact.cjs build "<目录>" --policy hide-all      # 全部隐藏整块（页面会空）
node scripts/redact.cjs build "<目录>" --policy keep-all      # 全保留，只看效果
node scripts/redact.cjs build "<目录>" --interactive          # 逐项问你
```

## 必须让用户决定的三种情况

### 1. 联系方式公开是**故意的**

求职简历里手机号本来就该给 HR 看。所以：

- **不要默认把联系方式删光**，那会让用户的白做
- 把命中清单给用户看，问一句："手机号和邮箱是打算公开给招聘方的吗？"
- 用户说是 → 用 `--policy mask-high` 或 `--interactive` 把它们设为 `keep`

### 2. 半敏感信息

出生年月、学校、公司：简历核心内容，但也确实能被社工利用。
**问用户**，不要替他决定。

### 3. 图片

人像照片是简历必需的，但**照片的 GPS 坐标不该公开**。

正确做法：**保留照片本身，剥离 EXIF/GPS 元数据**（默认行为）。
只有用户明确说"这张照片别放"才打码或删除。

## 一些容易忽略的泄露点

| 位置 | 例子 |
| --- | --- |
| `<meta>` 标签 | `<meta name="author" content="真实姓名">` |
| 图片 `alt` | `alt="张三的工作照"` |
| HTML 注释 | `<!-- 作者：张三 13800138000 -->` |
| 文件名本身 | `张三-简历.pdf`、`13800138000.jpg` |
| 链接里的参数 | `?token=xxx` |
| JSON-LD 结构化数据 | `<script type="application/ld+json">` 里的 email/telephone |
| 被排除但仍被引用 | 排除了 `_backup/` 但页面里还引用着 `_backup/a.jpg` |

最后一条由脱敏脚本自动处理：**摘除对被排除文件的引用**。

## 上线后还要复核

脱敏完不等于安全，因为：
- CDN / 浏览器缓存可能还是旧页面
- 可能有页面之外的入口（仓库里的其他文件、README、commit 历史）

```bash
node scripts/deploy.cjs "<目录>" --repo <仓库名> --forbidden "13800138000,demo@example.com,张三"
```

`--forbidden` 里的值会在上线后**抓真实链接逐条比对**，还有残留就报错。

> 更狠的一条：**commit 历史里也可能有**。如果曾经推过含真实手机号的版本，
> 即使后来删了，历史里还在。这种情况要用 `git filter-repo` 重写历史，或干脆删库重建。
