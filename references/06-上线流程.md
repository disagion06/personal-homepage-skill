# 06 · 上线流程（GitHub Pages）

---

## 前置条件

```bash
git --version        # 需要 git
gh --version         # 需要 GitHub CLI
gh auth status       # 必须已登录，且有 repo 权限
```

没装：

```bash
# Windows
winget install --id Git.Git -e
winget install --id GitHub.cli -e

# 登录（浏览器设备授权）
gh auth login --hostname github.com --git-protocol https --web
```

---

## 一条命令上线

```bash
node scripts/deploy.cjs "<脱敏后的目录>" --repo my-portfolio

# 带上线后复核
node scripts/deploy.cjs "<目录>" --repo my-portfolio \
  --forbidden "13800138000,demo@example.com,张三" \
  --report "脱敏报告.md"
```

脚本内部步骤（每一步都会打日志）：

```
git init → git add/commit → 仓库探测/创建 → git push
→ 开启 Pages → 轮询构建状态 → 强制 HTTPS → 抓真实链接复核敏感值是否消失 → 输出链接
```

---

## 链接形态

| 站点类型 | 链接 | 要求 |
| --- | --- | --- |
| 项目站点（默认） | `https://<用户名>.github.io/<仓库名>/` | 无特殊要求 |
| 用户站点 | `https://<用户名>.github.io/` | 仓库名必须**正好**是 `<用户名>.github.io` |

---

## 三条硬性限制

1. **免费账号的 Pages 要求仓库公开。** 私有仓库 Pages 不构建（Pro 才支持）。
2. **单文件 100MB 上限。** 超过直接 push 被拒。50MB 以上会明显拖慢。
3. **构建要等 1–3 分钟。** 刚 push 完点链接是 404 是正常的。

## 常见失败与处理

### `schannel: AcquireCredentialsHandle failed`

Windows 系统 TLS 后端在受限环境里拿不到凭据句柄。

```bash
git -c http.sslBackend=openssl push
```

### `Recv failure: Connection was reset` / `Could not connect to github.com:443`

网络到 `github.com:443` 不通（国内常见）。先判断范围：

```bash
Test-NetConnection github.com -Port 443    # 网页/仓库端
gh api rate_limit                          # API 端是否通
```

**如果 `gh api` 通、`github.com:443` 不通**，那创建仓库、开 Pages、查构建状态
都可以走 API，只有 `git push` 不行。这时用 REST 的 **Git Data API** 推送：

```
1. POST /repos/{owner}/{repo}/git/blobs      逐个上传文件（base64）
2. POST /repos/{owner}/{repo}/git/trees      用 blob sha 组装树
3. POST /repos/{owner}/{repo}/git/commits    创建提交
4. PATCH /repos/{owner}/{repo}/git/refs/heads/main
```

两个坑：
- **空仓库会拒绝创建 blob**，返回 `409 Git Repository is empty`。
  要先用 Contents API（`PUT /repos/{owner}/{repo}/contents/.gitignore`）落一次初始提交。
- `git ls-files` 默认把中文路径转义成 `\344\275\277...`，
  喂给 API 前要加 `-c core.quotepath=false`。

### `E_REPO_EXISTS`

仓库已存在。要么换个名字，要么加 `--reuse` 覆盖推送。

### Pages 链接 404，但仓库里有文件

| 原因 | 检查 |
| --- | --- |
| 构建还没跑完 | 等 1–3 分钟；或看仓库 Actions 页 |
| 根目录没有 `index.html` | 确认入口文件名 |
| 链接少结尾斜杠 | 项目站点要 `/` 结尾 |
| 仓库是私有的 | 改公开 |
| Pages 源目录设错 | Settings → Pages 应指向 `/`（或你 push 的那个目录） |

### 证书还没签发

新仓库的 HTTPS 证书要几分钟。程序会重试；仍失败只在日志留 warning，
**不影响网站可访问**。稍后手动到 Settings → Pages 勾 Enforce HTTPS。

## `.nojekyll` 是干什么的

GitHub Pages 默认跑一遍 Jekyll。Jekyll **会忽略以下划线开头的文件和目录**。

所以如果你的站点里有 `_backup/`、`_assets/`（下划线开头），它们会被静默排除 → 图片全裂。

放一个空的 `.nojekyll` 文件在根目录就能关掉 Jekyll。`scripts/redact.cjs` 会自动写这一个文件。

> 反过来说：**加了 `.nojekyll` 之后 `_backup/` 也会被公开访问**。
> 不想公开就**排除它**，别指望 Pages 帮你藏。

## 更之后的更新

改完页面重新上线：

```bash
node scripts/deploy.cjs "<新目录>" --repo my-portfolio --reuse
```

`--reuse` 会覆盖推送到已有仓库。Pages 会自动重新构建。
